# Limitless: техники магической битвы жестами рук

Приложение работает целиком в браузере: React, Vite, TypeScript, MediaPipe Hand Landmarker (две руки), Canvas 2D и Web Audio.

## Запуск

```bash
npm install      # заодно копирует MediaPipe WASM и скачивает модели (руки + сегментация человека) в public/
npm run dev      # откройте http://localhost:5173 (или порт, который покажет Vite)
npm test         # unit-тесты жестов, резолвера и машин состояний
```

Камера работает только на `localhost` или по HTTPS. После `npm install` сеть больше не нужна. Если модель не скачалась, приложение загрузит её с CDN при первом запуске. Модель сегментации необязательна: без неё вместо выреза человека используется маска рук по landmarks.

## Персонажи и жесты

Персонаж выбирается вверху экрана. Камера и трекинг при этом не перезапускаются, активные техники отменяются. Атаки запускаются только жестами. Кнопки нужны лишь для выбора персонажа, настроек и теста эффектов в debug-режиме.

### GOJO SATORU

| Жест | Результат |
|---|---|
| ☝️ Только указательный | **BLUE**: шар на указательном пальце |
| ✌️ Указательный + средний, разведены | **BLUE + RED**: по шару на каждом пальце |
| 🤞 Свести кончики и удерживать ~1 с | Слияние → **HOLLOW PURPLE** |
| ⚡ Резкий взмах / раскрыть ладонь / резкое движение пальцем | Выстрел |
| 🤞 **Скрестить** указательный и средний (безымянный и мизинец согнуты), 1,2 с | **UNLIMITED VOID** |
| ↳ запасной вариант: свести кончики **и повернуть кисть** (≥ ~22°), 1,2 с | то же |
| 🖐 Раскрытая ладонь 0,8 с | выход из Unlimited Void |

Hollow Purple и Unlimited Void не конфликтуют. Касание кончиков без поворота кисти — это Purple. Скрещивание, то есть обратный порядок кончиков вдоль линии костяшек, или касание с поворотом — это Void. Void прерывает Blue/Red, пока Purple ещё не сформирован. Уже активный Purple он не прерывает.

### RYOMEN SUKUNA

| Жест | Результат |
|---|---|
| ✌️ Два пальца → резкий взмах в любую сторону | **DISMANTLE** по реальной траектории пальцев; три подряд → **TRIPLE DISMANTLE** |
| 🙏 Обе руки: указательный + средний вверх, остальные согнуты, ладони рядом, симметрично, на одной высоте, 1,5 с | **MALEVOLENT SHRINE** (8 с) |

### ALL TECHNIQUES

Доступны все техники. Приоритет такой: двуручные печати, затем расширения территории, затем заряжаемые техники, затем одиночные атаки. Сложные печати требуют на 25 % более долгого удержания. Поза «два пальца» одинакова у Red и Dismantle, поэтому её владельца выбирают в настройках.

## Как устроено распознавание

```
MediaPipe (1 экземпляр, numHands 2, VIDEO)
  → HandProcessor      сглаживание One Euro, слоты рук по близости и handedness, центр ладони (0,5,9,13,17),
                       углы суставов (worldLandmarks при наличии), скорости, ускорение, скорость роста ладони,
                       метрика скрещивания пальцев, нормаль ладони
  → GestureClassifier  кандидаты жестов с уверенностью и гистерезисом входа/выхода
  → GestureResolver    один победитель: персонаж → блокировки → приоритет → уверенность,
                       временной фильтр, подтверждение удержанием при неоднозначности, причины отклонения
  → техники            машины состояний (TypeScript-union состояний), cooldown, «защёлка» от зацикливания
  → Effect Engine      один цикл rAF, пулы объектов, тёмный и световой проходы
```

Все пороги лежат в [src/engine/config.ts](src/engine/config.ts). Расстояния там заданы в ширинах ладони, скорости — в ширинах ладони в секунду, поэтому от расстояния до камеры они не зависят. В настройках есть общие множители удержания и порога скорости. Отдельные значения можно менять прямо в консоли браузера: `__gojo.cfg.DISMANTLE.SPEED_IN = 8`.

Кратковременная потеря рук техники не отменяет: короткие пропуски покрывает grace на позу 180 мс. Если рук нет дольше 500 мс, отслеживаемые эффекты гаснут, а незавершённые жесты отменяются. Призванный сикигами и активный домен доигрывают сами.

## Архитектура

Структура адаптирована под существующий проект, без лишнего рефакторинга. Исходные Blue, Red и Purple (`abilityMachine.ts`, `effects.ts`) не переписаны: машина обёрнута как техника `limitless`.

```
src/engine/
  handTracker.ts       MediaPipe Hand Landmarker (две руки), общий WASM fileset
  segmenter.ts         ленивая сегментация человека: только пока виден домен и профиль не LOW
  hands.ts             HandProcessor: геометрия, суставные углы, скорости, скрещивание
  gestures.ts          исходный классификатор пальцев (гистерезис, debounce)
  gestureClassifier.ts кандидаты всех жестов
  gestureResolver.ts   выбор одного жеста, приоритеты, комбо, вытеснение, неоднозначность
  core.ts              конвейер без DOM (используется и в тестах)
  characters.ts        персонажи и наборы техник
  config.ts            все пороги
  techniques/          base, limitless, unlimitedVoid, malevolentShrine, dismantle, blackFlash, tenShadows, piercingBlood
  fx/
    api.ts             контракт Fx/Sfx между техниками и эффектами
    effectManager.ts   единый Effect Engine
    primitives.ts      Shockwave, SlashTrail, EnergyBeam, ElectricArc, Cracks, EnergyOrb, Portal, HandAura, ScreenDistortion
    particles.ts       пул частиц (типизированные массивы, без аллокаций)
    domains.ts         DomainEnvironment: космос Void, святыня (программный 3D: перспектива, отсечение, сортировка)
    shikigami.ts       SummonEffect: псы, Нуэ, жаба (процедурные 2D-силуэты)
    personLayer.ts     вырез человека или рук поверх домена
  engine.ts            цикл: камера → ядро → рендер → HUD
  audio.ts             процедурный звук: прежние слои и новые one-shot-звуки и фоны
src/components/        Hud, CharacterSelector, SettingsPanel, GestureDebugger, CinematicTitle, IntroScreen
```

## Графика и производительность

- **AUTO** снижает число частиц и детализацию, когда рендер падает ниже 45 FPS, и повышает их обратно.
- **HIGH**: максимум частиц, 3 туманности, галактики, вращающиеся структуры, искажение изображения, сегментация на каждом кадре.
- **MEDIUM**: меньше частиц, сегментация через кадр.
- **LOW**: DPR 1, минимум частиц, без искажений и сегментации, святыня из закешированного 2.5D-слоя.
- Трекинг не вызывает React-рендер на каждом кадре: HUD обновляется 10 раз в секунду, данные лежат в ref. При размонтировании отменяется rAF, закрываются MediaPipe и AudioContext, останавливается камера.
- Фиксированный FPS не гарантируется: он зависит от устройства.

## Тесты и что проверено

`npm test` прогоняет 53 теста на синтетических последовательностях landmarks: дрожание ±3 px, пропущенные кадры, потеря рук, конфликтующие жесты. Тесты охватывают классификацию всех жестов, отличие скрещивания от касания, отказ на случайных позах (сближенные ладони, сжатый кулак, медленные движения), приоритеты резолвера, cooldown, защиту от повторных выстрелов и зацикливания, смену персонажа, а также smoke-тест рендеринга всех эффектов на мок-холсте (отсутствие ошибок, опустошение пулов).

**Физические жесты на реальной камере автоматически не проверялись.** Пороги подобраны на синтетической модели руки и требуют ручной донастройки: включите debug-режим (🐞), там видны состояние пальцев, уверенность и причины отклонения.

## Ограничения

- Одна RGB-камера плохо видит глубину. Поэтому удар Black Flash «вперёд» определяется по росту ладони в кадре, а скрещивание пальцев дополнено запасным вариантом с поворотом кисти. `worldLandmarks` у MediaPipe центрированы на руке, поэтому они уточняют углы суставов и нормаль ладони, но не дают перемещения в глубину.
- Ладони, направленные друг к другу, в печати святыни учитываются как мягкий бонус к уверенности, а не как обязательное условие.
- Святыня — программная low-poly-модель, сикигами — процедурные 2D-силуэты. Сторонние 3D-модели не используются, поэтому вопрос прав на ассеты не возникает. Three.js не подключался: эффекты работают на Canvas 2D со спрайтовым свечением, и одного цикла рендеринга хватает.
- Без сегментации человек не может оказаться «внутри» домена целиком: видны только руки, а окружение остаётся полупрозрачным.
